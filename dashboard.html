"Reached cap" means the position's mark-to-market value crossed max_position_pct at some point — the cap only ever blocks a new order once a ticker is at it (see "sized to zero after risk caps" / "max position pct reached for this ticker" in the decision feed below); it can't shrink a position that's already open and has since moved. A peak noticeably above the cap with no corresponding fill right before it is ordinary price drift on an unchanged position, not a sizing bug — check the per-ticker signal trace and decision feed for that ticker's fill history before assuming otherwise.

This is a read-only log viewer, with one deliberate exception. It only ever reads whatever decisions.jsonl you load (or, in the "LIVE" badge above, polls from scripts/serve_dashboard.py) — it never writes to that file and has no direct connection to the trading process. The one write this page can do is the Reset kill switch button shown next to a HALTED badge in live mode: clicking it (after a confirmation prompt) asks serve_dashboard.py to drop a request file that run_live_alpaca.py picks up and acts on itself, on its own next bar, via RiskManager.reset_kill_switch(human_confirmed=True) — this page never flips that state directly, and the button only appears while actually live and halted.

Nothing here is investment advice, and a positive backtest or paper-trading number is not a guarantee of future results.

Process logs

Stdout from run_live_alpaca.py, serve_dashboard.py, and premarket_check.py -- the files that would otherwise need opening by hand to see a reconnect error, a restart, or the per-ticker warm-up/connect lines those scripts print. Each line is leveled (dot) and tracebacks collapse to one entry. Only available while this page is served by scripts/serve_dashboard.py (not when a log file was dropped/loaded manually).
